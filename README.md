# オウチカエル

現在地から、いつもの目的地までの「徒歩・発・着・終電」をひと目で確認するApple向けMVPです。

## 起動

1. `Ouchikaeru.xcodeproj` をXcodeで開きます。
2. `Ouchikaeru` SchemeとiPhoneシミュレータを選択して実行します。iOS 17 / watchOS 10以降が対象です。
3. 全画面の地図で住所を検索し、検索結果または地図のタップで地点を選んで「この住所を登録」を押します。名前の入力は不要です。登録後、目的地名の横の鉛筆ボタンから「自宅」などに変更できます。
4. 位置情報を許可します。シミュレータでは **Features → Location → Custom Location** で日本国内の現在地を設定してください。
5. ホーム画面に「オウチカエル」のWidgetを追加します。Watchはペアリングしたシミュレータで `OuchikaeruWatch` Schemeを実行します。

アプリ上部に目的地変更・再読み込み・4段階の進行状況・更新エラーを固定表示します。通常経路と終電は出発、乗車、目的地到着を横並びで表示し、到着には降車後の徒歩を含みます。進行状況は処理段階であり、残り時間の割合ではありません。

シミュレータの固定位置は設定時の古い日時を返すことがあるため、シミュレータでのみ位置の日時による除外を行いません。実機では引き続き120秒以内の位置情報を待ち、取得後に測位を停止します。

外部パッケージ、APIキー、バックエンドは不要です。APIへの通信にはネット接続が必要です。

シミュレータの初期位置は米国になっている場合があります。東京を出発地にする場合は **Simulator → Features → Location → Custom Location** で緯度 `35.681`、経度 `139.767` を設定してください。起動中のシミュレータ1台にターミナルから設定する場合は `xcrun simctl location booted set 35.681,139.767` も使えます。アプリは日本周辺の範囲外の座標を検出すると、経路検索前に設定を案内します。範囲内でも交通データが存在する保証はありません。

`WCSession is not paired` はApple Watchが未ペアリングの場合の警告です。iPhoneの位置取得・経路検索の失敗とは独立しています。

### 実機の署名

Xcodeの各ターゲットのSigning & Capabilitiesで自分のDevelopment Teamを設定してください。初期Bundle IDは `jp.ouchikaeru.app`、Widgetは `.widget`、Watchは `.watchkitapp` です。実機で利用する識別子に変更する場合は、Watchの `WKCompanionAppBundleIdentifier`、iPhone/WidgetのApp Group entitlement、`Shared/SharedStore.swift` のグループ名も一致させます。App Groupの初期値は `group.jp.ouchikaeru.app` です。

## 実装

- iPhone: 目的地1件の登録・置換・永続化、住所施設検索、地図選択、単発の現在地取得、通常経路・終電検索、乗換表示、手動更新、起動/Foreground更新。
- アプリ表示中は60秒ごとに鮮度を確認し、5分経過または徒歩出発期限を過ぎた情報を更新します。常時GPS追跡は行いません。
- Widget: small / medium。App Groupに保存した同じ経路を表示し、期限に合わせたTimelineで「要更新」を表示します。タップでiPhoneアプリが開きます。
- Watch: iPhoneから目的地と最新経路を受け取り、Watch自身の現在地と通信で経路を自動更新します。Watch端末にも最後の経路を保存し、未設定時の案内、最終更新日時、古い経路の表示に対応します。
- 失敗時: 前回の成功データを残し、位置権限拒否、取得失敗、候補なし、終電取得失敗を区別します。目的地の変更時は以前の目的地の経路をWidget/Watchも含めて破棄します。
- 通常経路は終電の検索完了を待たずに表示・共有します。「現在地を取得中」「駅と徒歩ルートを確認中」「経路を検索中」「終電を確認中」で処理状況を表示します。

`Sources/TransitCore` はFoundationのみのモデル・APIクライアント・経路変換です。Xcodeの各ターゲットはこのソースを共有し、Swift Packageでは独立してテストします。`iPhone`、`Widget`、`Watch` が各画面、`Shared` が保存と同期、共通表示です。

## APIと時刻

[Transit APIの公開仕様](https://api.transit.ls8h.com/api/openapi.json)に従い、`GET /api/v1/plan` に駅ID、サービス日、時刻、通常経路では`type=departure`、終電では23:59:59の`type=arrival`を渡します。対象モードはrail/subway/tram/monorailです。場所検索は `GET /api/v1/places/suggest?q=...` を使います。

### 駅間検索と徒歩

`StationRouter` は両端の `places/reverse`（半径500m、10候補）で駅を探し、最大3駅名を `locations/suggest` で交通APIの駅IDに解決します。その中から直線距離が最も近い物理駅を1つ選び、同じ駅に路線別IDが複数ある場合はAPIの重みが最も高い代表IDを使います。徒歩は `MKDirections` のwalkingを使い、出発側は分単位への切り上げとホームまでの余裕1分を加えます。駅間検索には徒歩後の時刻を渡し、降車後の徒歩は最終到着に加算します。

通常経路は最寄りの出発駅と到着駅の1組だけを駅IDで検索します。駅ID検索を400ミリ秒先行させて座標検索も並行し、先に利用可能になった方を採用します。これにより、大駅の路線別IDを総当たりしていた待ち時間をなくしつつ、代表IDで検索できない場合は座標検索へ戻れます。終電は通常経路で実際に使われた乗降駅IDを最優先し、23:59までに到着する最後の有効経路を検索します。座標検索で得た乗降駅IDも再利用します。

駅が見つからない、徒歩が取得できない、利用できる駅間経路がない場合は従来の座標検索へ切り替えます。座標検索は最大60秒です。駅から離れた住所やAPI未収録の場所ではこちらが使われるため、初回が常に高速になるわけではありません。

駅候補と徒歩のキャッシュはメモリ上に現在の両端分だけ保持します。駅候補は取得地点から100m以内・1時間、徒歩はGPSの揺らぎを考慮して50m以内なら再利用し、それ以上の移動後は再計算します。最もよい経路で実際に乗降した駅IDの組み合わせを同一座標・同日で5分間再利用します。また、再起動後も保存済み経路と目的地が同じで現在地が150m以内なら、前回実際に使えた駅IDの組み合わせを2秒上限で最初に検索し、利用できない場合だけ通常検索へ進みます。この間も列車の時刻は再検索します。終電結果は同一座標・同日で10分間再利用します。

サービス日と応答のタイムゾーンを使い、秒数から絶対時刻へ変換します。86400超過と負数に対応しています。最初と最後の鉄道区間を出発・到着駅とし、地理的なaccess/egress徒歩と、乗車前/降車後の徒歩区間を合算します。徒歩で乗車駅に間に合う候補のうち、最終到着が最も早い経路を採用します。

終電は現在地を出る期限も表示します。空の検索結果やAPI失敗だけでは「本日の終電は終了」と断定しません。取得済み終電の徒歩出発期限を過ぎた場合に終了を表示し、前日の情報は更新を案内します。深夜0時以降はAPIへの問い合わせ日の終電を対象とします。

交通データの提供元と帰属は[APIのfeedsエンドポイント](https://api.transit.ls8h.com/api/v1/feeds)で確認できます。アプリ内の案内からもリンクしています。

## 検証

```sh
swift test
xcodebuild -project Ouchikaeru.xcodeproj -scheme Ouchikaeru \
  -sdk iphonesimulator -configuration Debug \
  -derivedDataPath /tmp/ouchikaeru-derived CODE_SIGNING_ALLOWED=NO build
```

経路変換テストは、日付跨ぎ、負のサービス秒、徒歩時間の重複回避、降車後の駅間徒歩、乗車可能性と到着順、異なる駅への乗換、キャッシュの往復と期限を検証します。

### アプリ画面での実APIテスト

`OuchikaeruUITests` は、目的地未登録時に画面から東金を検索・登録し、実際の経路の到着時刻が表示されることと、アプリ再起動後の目的地・経路の保持を確認します。目的地が登録済みの場合は登録を置き換えません。ネット接続と、日本国内に設定したシミュレータの現在地が必要です。XcodeでiPhoneシミュレータを選び、Product → Test（⌘U）から実行できます。

コマンドラインの `CODE_SIGNING_ALLOWED=NO` はコンパイル確認専用です。そのビルドをシミュレータへインストールするとApp Groupが使えず、共有保存先が変わる可能性があります。起動・UIテストには通常のXcode Run/Test、または `CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=-` のシミュレータ署名付きビルドを使用してください。

プロジェクトを再生成する場合は `python3 Scripts/generate_project.py` を実行します。これは `Config` 内のplist/entitlementとXcode設定も初期値で生成するため、署名設定などを変更した場合はスクリプト側にも反映してください。

### 実機での受け入れ確認

- 目的地登録後に再起動して保持されること、変更すると古い経路が消えること。
- 位置権限を拒否した場合に設定への案内が出ること。
- 通信を切断して更新すると前回の経路と取得失敗の案内が出ること。
- Widgetを追加してiPhoneと一致する経路が表示されること。
- Watchをペアリングして、iPhoneで設定した目的地と経路が届くこと。iPhoneとの接続を切った状態でも、Watchの位置情報と通信だけで経路を更新できること。
- 翌日表示、文字サイズを大きくした表示、VoiceOverの読み上げ。

## MVPの制約

Widgetはネット検索や現在地取得を行わず、iPhoneが最後に取得した情報を表示します。OS管理の更新でリアルタイム性は保証しません。Watchはアプリの起動中に経路を自動更新しますが、バックグラウンドでの常時更新は行いません。Watch Complicationは未実装です。運行データの欠落や予定時刻と実際の差はあり得ます。

App Store配布用アイコン、配布署名、実機でのWidget/Watch同期の最終確認はリリース前に必要です。
